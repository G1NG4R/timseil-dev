SYS.00.09.01 ZWEI WEGE ANFRAGE UND DEPLOY BERÜHREN SICH NUR AN EINER STELLE: DEM CONTAINER
ANFRAGEWEG
BROWSER → DNS grau, kein Proxy → TRAEFIK :443 · TLS → NEXT.JS app → OPS-API → POSTGRES alles auf einem Host, ein Docker-Netz
Nach außen sind nur 80 und 443 offen; 80 leitet auf 443 um. Der Container spricht nie direkt mit dem Netz, Traefik terminiert TLS. Kein Drittanbieter im Anfrageweg — genau das behauptet die Datenschutzseite, und genau deshalb steht DNS auf grau statt auf Proxy.
DEPLOY-WEG
PUSH AUF MAIN → ACTIONS lint · build · test → IMAGE → GHCR sha-Tag → DOKPLOY-WEBHOOK → PULL & SWAP → HEALTHCHECK
Der Build läuft in Actions, nicht auf dem VPS — der Server soll ausliefern, nicht kompilieren. Image-Tag ist der Commit-SHA, nie latest: nur so ist Rollback ein Deploy und kein Rätsel. Dokploy legt pro Dienst eine Webhook-URL an, die Actions am Ende aufruft.

SYS.00.09.03 METRIKEN EIN SYSTEM KANN SEINE EIGENE VERFÜGBARKEIT NICHT BESTÄTIGEN
UPTIME · VON AUSSEN
Externer Monitor, HTTP GET /, 60s
Standort außerhalb des VPS
Fenster: 24h · 30d · 90d
Warum außen: fällt der Host aus, fällt auch jeder Messwert auf dem Host aus. Selbstauskunft wäre wertlos
P95 · AUS TRAEFIK
Traefik Access-Log als JSON
Job alle 5 min aggregiert nach SQLite
p50 · p95 · p99 pro Route
Kein Prometheus, kein Grafana: für einen Host und vier Dienste ist eine Tabelle mit Perzentilen ehrlicher als ein Dashboard-Zoo
ERROR RATE · GLEICHE QUELLE
5xx geteilt durch alle Anfragen
4xx getrennt, zählt nicht als Fehler
Fenster 24h, gleitend
404 ist kein Ausfall. Wer 4xx in die Fehlerrate rechnet, misst Besucher statt Systeme
Der Weg auf die Seite: /api/health liest den Aggregat-Stand, mischt die Uptime des externen Monitors dazu und antwortet mit s-maxage=60, stale-while-revalidate=600. Dokploys eigene Container- und Server-Metriken bleiben im Panel — sie beantworten „läuft der Host", nicht „wie schnell antwortet die Route". Fehlt ein Wert, rendert die Kachel — NO DATA; Zahlen werden nie geschätzt.

SYS.00.09.05 DOMAIN, TLS, MAIL
DNS-EINTRÄGE
A timseil.dev VPS-IPv4 AAAA timseil.dev VPS-IPv6 CNAME www timseil.dev CAA timseil.dev letsencrypt.org TXT @ v=spf1 include:… -all TXT resend._domainkey DKIM des Providers TXT _dmarc p=none → p=quarantine MX @ Postfach-Provider
TLS übernimmt Traefik über Let's Encrypt, automatisch erneuert. Nur TLS 1.2 und 1.3, HTTP leitet um. HSTS erst einschalten, wenn die Domain final ist — vorher ist es ein Fußschuss mit langer Laufzeit. CAA begrenzt, wer überhaupt Zertifikate ausstellen darf.
Mail läuft zweigeteilt: das Formular über einen Transaktions-Provider mit SPF, DKIM und DMARC, das Postfach contact@timseil.dev getrennt davon. DMARC startet auf p=none mit Reports, nach zwei Wochen ohne Auffälligkeiten auf quarantine. Reply-To trägt die Adresse des Absenders.
SYS.00.09.06 RUNBOOK UND STOLPERSTEINE DIE VIER HANDGRIFFE, DIE MAN NACHTS BRAUCHT
DEPLOY
Push auf main. Actions baut, taggt mit SHA, ruft den Webhook. Dokploy zieht und tauscht. Healthcheck muss grün werden, sonst bleibt der alte Container.
ROLLBACK
Im Panel den vorherigen SHA-Tag deployen. Kein Git-Revert nötig, kein Build. Deshalb niemals latest.
RESTORE
Dump aus dem Objektspeicher holen, in eine frische Datenbank spielen, App auf sie zeigen lassen, dann umschalten. Monatlich geübt.
INCIDENT
Alarm vom externen Monitor → Traefik-Log → Container-Log → Ressourcen. Danach eine Zeile im Log der Seite: was, wie lange, was geändert.
FÜNF STOLPERSTEINE, DIE IN DOKPLOY-SETUPS REGELMÄSSIG AUFTRETEN
▸ Container muss im Netz dokploy-network liegen und das Label traefik.docker.network=dokploy-network tragen — sonst finden sich Proxy und Dienst nicht
▸ Container-Port explizit setzen. Bei mehreren offenen Ports rät Traefik falsch, das Ergebnis sind Timeouts
▸ Volumes relativ als ../files/… mounten. Absolute Pfade räumt Dokploy beim Redeploy unter Umständen weg
▸ acme.json braucht Rechte 600, sonst verweigert Traefik die Zertifikatsablage
▸ Alte gestoppte Container mit Traefik-Labels erzeugen Routing-Konflikte — nach Umbauten aufräumen
Quellen: Dokploy-Dokumentation und drei Erfahrungsberichte, abgerufen 15.08.2026 — nicht aus dem Gedächtnis
GEHEIMNISSE
▸ GITHUB_TOKEN mit read:user — nur für den Contribution-Graph, serverseitig, kein NEXT_PUBLIC_
▸ MAIL_API_KEY für das Formular, DATABASE_URL für die API — in Dokploy pro Dienst, nie im Repo
▸ Webhook-Token als GitHub-Secret. Wer den kennt, kann deployen
▸ Dokploy-Panel auf eigener Subdomain, Zwei-Faktor an, SSH nur mit Schlüssel, Root-Login aus
