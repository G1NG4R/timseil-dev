1dDesign notes
DESIGN NOTES — HOMEPAGE
▸ BOOT-KASKADE: die Seite lädt wie ein Dienst — SYS.INIT-Zeilen, dann Hero, dann Module. Die Überschrift dekodiert aus Zufallszeichen und wird nach jedem Render neu auf den Endzustand gesetzt
▸ TERMINAL statt Spielerei: whoami · stack · projects · work · blog · about · cv · help — echte Ausgaben, jede Zeile ein Fakt, den die Seite belegen kann
▸ CV NUR ÜBER DAS TERMINAL: der Befehl cv lädt die PDF direkt — es gibt keine CV-Seite, keinen Knopf, keinen Nav-Eintrag und keinen Eintrag in der 404-Routenliste. Fußzeile Desktop: CV → TERMINAL cv auf der Startseite, sonst mit Ortsangabe CV → TERMINAL AUF / : cv. Mobil ist das Terminal read-only, deshalb verlinkt die Mobil-Fußzeile direkt CV → cv.pdf — eine Anweisung, die auf dem Gerät nicht ausführbar ist, wäre eine Sackgasse
▸ THEME-WAHL in der Fußzeile jeder Seite, sieben Paletten, Auswahl liegt in localStorage (ts.theme) — Terminal Noir bleibt verbindlich, die anderen sind Angebot
▸ EHRLICHE SYSTEMLISTE: 02 SYSTEMS — nur timseil.dev ist LIVE, vat-check steht auf QUEUED und trägt darum keine Betriebszahlen, sondern — NO DATA
▸ TRAININGS-LOG als Fundament der Seite: 22 Tracks in fünf Modulen, Zustand und Balken sagen dasselbe, und jede Zeile nennt ihren Beleg. Heute 13× APPLIED aus timseil.dev, 9× LEARNING ohne System, nichts auf CORE — der Log füllt sich mit jedem Projekt
▸ EIN ALERT-MOMENT: YOU ARE INSIDE THIS PROJECT in Rot, sonst trägt Cyan unter 3 % Fläche die Akzente
1eAbschnittsfolge — verbindlich, auch für Kopien
HOME.01 ABSCHNITTSFOLGE DIE NUMMER IST DIE REIHENFOLGE
HERO Aussage, Stack, Verfügbarkeit, Terminal. Wer hier abbricht, hat den Satz gelesen. SYS.01 TRAINING LOG — 22 Tracks mit Beleg. Steht vor der Systemliste, weil er die Belege liefert, auf die sie sich beruft. SYS.02 SELECTED WORK — die Systeme, auf die der Log zeigt. Von hier führt der Weg in die Fallstudie. SYS.03 UPLINK — Contribution-Graph und Betriebsstreifen. Aktivität und Betrieb, zwei Blöcke, jeder nennt seine Quelle. SYS.04 LOG — drei Einträge. Steht zuletzt, weil er der laufende Teil ist, nicht der beweisende. FUSS Bio mit Porträt, Kontaktblock, Meta-Leiste — Fassung „lang" aus dem Chrome-Blatt.
▸ DIE NUMMER IST DIE REIHENFOLGE: SYS.01 → 02 → 03 → 04, ohne Ausnahme. Wer eine Sektion verschiebt, vergibt eine neue Nummer — sonst zeigt die Seite eine Ordnung, die sie nicht einhält
▸ BELEG VOR BEHAUPTUNG: der Log steht vor der Systemliste. Genau diese Folge ist das Argument der Seite; dreht man sie um, wird aus Nachweis wieder Selbstbeschreibung
▸ KOPIEN FOLGEN DER QUELLE: das Themes-Blatt und jede spätere Variante übernehmen diese Folge. Weicht eine Kopie ab, ist die Kopie falsch, nicht die Startseite
▸ GEPRÜFT WIRD MIT EINEM BLICK: die vier Marker müssen auf der Seite in aufsteigender Reihenfolge stehen. Das ist der ganze Test
