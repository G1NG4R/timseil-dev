SYS.00.04.04b DER KERN WER DAS WEGLÄSST, BAUT EIN ANDERES PRODUKT

Jede Behauptung der Seite ist an einen Beleg gebunden, und der Beleg ist ein System, das läuft. Der Trainings-Log ist damit keine Selbsteinschätzung, sondern eine Ableitung — und er ist die zeitliche Achse der Seite.

0122 TRACKS IN FÜNF MODULEN
01 LANGUAGES · 02 BACKEND · 04 DEVOPS · 03 DATA · 05 FOUNDATIONS. Jeder Track trägt einen Zustand — CORE · APPLIED · LEARNING · QUEUED — und Zustand, Balkensegmente und Belegzeile sagen immer dasselbe.
02BELEGZEILE: TRACK → SYSTEM
Unter jedem Track steht, wo er läuft: SHIPPED IN → 02 TIMSEIL.DEV (BUILD + DEPLOY). Ohne System: NO SYSTEM YET → SELF-STUDY. Das ist eine Beziehung in den Daten, kein Text im Markup.
03DER LOG FÜLLT SICH MIT JEDEM PROJEKT
Kommt ein System hinzu, wandern die Tracks, die es benutzt, von LEARNING auf APPLIED, und die Belegzeile nennt das neue System. CORE ist erst ab zwei Systemen im Betrieb erreicht — deshalb steht heute kein Track auf CORE. Stand: 13 APPLIED aus timseil.dev, 9 LEARNING, 0 CORE.
04BETRIEBSZAHLEN NUR FÜR LIVE
Uptime, p95 und Fehlerrate trägt nur ein System mit öffentlicher Adresse und Health-Check. QUEUED und IN BUILD zeigen — NO DATA. Erfundene Zahlen sind ausgeschlossen; Platzhalter stehen in […].
05BETRIEBSRASTER STATT AKTIVITÄTSGRAPH
Eine Zelle je Betriebstag, eine Kerbe je Ausfall — anklickbar mit Ursache, Behebung, Error-Budget und Log-Eintrag. Ohne Post-Mortem keine Kerbe. Fenster 91 Tage = 13 Wochen; Startseite 30 Tage als reine Anzeige. Der Contribution-Graph bleibt daneben: er misst Aktivität, das Raster misst Betrieb.
06JEDE ZAHL IST NACHZÄHLBAR
Uptime, MTTR, Rollback-Rate und Trainings-Zustände werden aus den Daten gerechnet, nie getippt. Deshalb steht überall dasselbe Fenster (91, nicht 90) und dieselbe Anzahl Belege — wer nachzählt, findet die Zahl, die dasteht.
SYS.00.04.05 DATENVERTRÄGE BEIDE QUELLEN VOM AUFTRAGGEBER BESTÄTIGT
01 OPS-METRIKEN EIGENER ENDPOINT
GET /api/health s-maxage=60, stale-while-revalidate=600 { "generatedAt": "2026-08-16T09:14:02Z", "systems": [ { "slug": "timseil.dev", "state": "live", "uptime90d": 99.64, "p95Ms": 142, "errorRate": 0.0007, "lastDeploy": { "sha": "a41f9c2", "durationSec": 42 } }, { "slug": "vat-check", "state": "queued" } ] }
Metriken werden nur für state: live gerendert. Fehlt ein Feld: „— NO DATA", nicht 0. Bei 5xx: letzter gültiger Wert plus Zeitstempel und Retry-Zähler. Form ist Vorschlag — der Endpoint existiert noch nicht.
02 CONTRIBUTION-GRAPH GITHUB, SERVERSEITIG GECACHT
POST https://api.github.com/graphql Authorization: Bearer <PAT scope read:user> query($login: String!) { user(login: $login) { contributionsCollection { contributionCalendar { totalContributions weeks { contributionDays { date contributionCount contributionLevel } } } } } }
Die REST-API liefert diese Daten nicht — geprüft, Quellen im README. Token nie clientseitig, kein NEXT_PUBLIC_. contributionLevel passt auf die 5 Stufen; die von GitHub gelieferten Farben nicht verwenden.
03 KONTAKTFORMULAR EIGENER ENDPOINT
POST /api/contact { "name": "2–80", "email": "≤254", "message": "20–4000", "company": "MUSS leer (honeypot)", "dwellMs": "≥3000", "ts": "ISO" } 202 { ok, id: "msg_01K3F9QX7A" } 400 { errors: { email } } 429 { retryAfter } + Retry-After 502 { code }
Ersetzt mailto:, das ohne eingerichtetes Mailprogramm stumm scheitert. Rate-Limit 3/10min, Timeout 8s, Idempotenz über ts + email + Hash. Zustellbarkeit ist die Arbeit: Provider plus SPF und DKIM, sonst Spam-Ordner.
04 TRAININGS-LOG DER KERN
GET /api/training { "modules": [ … 5 ], "tracks": 22, "track": { "name": "CI/CD (GitHub Actions)", "state": "applied", "evidence": [ { "systemNo": "02", "systemId": "timseil.dev", "detail": "BUILD + DEPLOY" } ] } }
state wird aus evidence.length abgeleitet: 0 lernend, 1 applied, ab 2 core. Nie separat setzen — sonst driftet die Anzeige von der Wahrheit ab. Heute: 13 applied, 9 learning, 0 core.

VOR LIVEGANG ENTSCHIEDEN · UMGESETZT INHALTSENTSCHEIDUNG, KEINE DESIGN-ÄNDERUNG

Frühere Entwürfe zeigten fünf Systeme, davon vat-check als LIVE mit Uptime, p95 und Fehlerrate — diese Systeme existieren nicht. Umgesetzt am 16.08.2026: die drei nicht existierenden Systeme sind gelöscht, es bleiben zwei. 01 vat-check steht auf ○ QUEUED und zeigt — NO DATA, 02 timseil.dev ist das einzige LIVE-System. Zähler, Filter-Chips und der Terminal-Befehl sagen dasselbe: only live systems carry ops metrics — today that is 02.

Der Weg, der die Idee intakt hält: timseil.dev ist das erste echte System. Die Seite läuft auf dem eigenen Stack, hat einen echten Deploy, echte Uptime und einen echten p95 — deshalb belegt der Trainings-Log heute 13 Tracks aus ihr und keinen aus einem Projekt, das es nicht gibt.
