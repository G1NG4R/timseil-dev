04.01 PROBLEM

A portfolio that only shows screenshots asks the reader to take the engineering on trust. For a backend and platform role that is the wrong thing to ask: the parts worth judging are service boundaries, deploys, and what happens at three in the morning when a container dies.

So the site had to be a running system rather than a description of one. The front end is a client of a real API. The API has its own database, its own container, its own health check. The infrastructure is mine to break: DNS, TLS, reverse proxy, logs, backups, restarts.

The second constraint was honesty. Nothing on the page is allowed to be a decorative number. If a value is shown, something has to produce it — the training log comes from a tracked file served by the API, the contribution graph from the GitHub API, uptime from the monitor.

CONSTRAINTS
01One VPS. No managed platform, no serverless.
02Every displayed value has a source.
03Deploy must be one command and one rollback.

DECISIONALTERNATIVEWHY THIS ONE
Go API as its own service API routes inside the React Router app A real service boundary is the thing being demonstrated. The same endpoints serve the site, the terminal, and anything else later.
Docker Compose on one VPS Managed hosting, or Kubernetes from day one I wanted to own the runtime: proxy, TLS, logs, restarts. Compose stays small enough to reason about and maps cleanly onto k8s later.
PostgreSQL, not SQLite A single SQLite file on the host Same engine as the other services, so migrations, backups, and restore drills transfer instead of being one-offs.
Deploy by image tag git pull and rebuild on the host Builds belong in CI. The host only pulls a tagged image, so a rollback is one tag and no build.

    env_file: .env.prod
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:8080/healthz"]
      interval: 10s
    depends_on:
      db: { condition: service_healthy }

04.05 RESULT
WHAT HOLDS
Push to live is one pipeline with a health gate, and a rollback is a tag change.
The API is the only source of data on the site, so nothing displayed can drift from what is tracked.
Local and production run the same compose topology, which removed a whole class of surprises.
WHAT I WOULD CHANGE
Structured logs and request tracing from the first commit, not after the first incident.
A staging target on the same host — right now verification happens against production.
Move the ambient WebGL layer behind an explicit budget check on low-end devices.
